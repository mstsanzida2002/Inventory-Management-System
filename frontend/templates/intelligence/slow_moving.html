Classification rules

Two layers, in order — not machine learning. Recalculated on every sale approval, and on demand via "Run classification now." No scheduler runs this automatically; a product that simply stops selling keeps its last classification until one of those two triggers fires again.

1. Override rules (checked first, on raw signals)

No sale in ≥ {{ dead_threshold }} days, or never sold and in stock ≥ {{ dead_threshold }} days (stock on hand) Force dead
≥ {{ extreme_coverage_days }} days of stock on hand — unless the index below already calls it dead on its own Force slow
Sold within the last 14 days, and ≤ {{ target_days_of_cover }} days of cover Force fast

2. Not old enough to score

In stock < {{ min_observation_days }} days, and no override above fired Insufficient data

3. Weighted stagnation index (0–100) — only when nothing above decided it

Index < {{ slow_index_threshold }} Fast-moving
Index {{ slow_index_threshold }}–{{ dead_index_threshold|add:"-1" }} Slow-moving
Index {{ dead_index_threshold }}+ Dead stock

The index blends four factors — recency, turnover, coverage (days of stock on hand vs. recent demand), and sale frequency (distinct weeks with a sale, not raw event count) — each scored 0–1 and combined using the weights set in System Settings. A row flagged by an override rule shows the reason in place of the index (e.g. "No sales in 210 days") — worth more than an opaque number.
